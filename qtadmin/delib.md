# 内部管理周会议事

本案例记录量潮内部管理周会的议事与留档流程：一次周会交付三件事——一份会议纪要文档、一场提案讨论与投票、一条大群结果播报。会议由每周确认的主持人与书记员运转，全程留痕，结论沉淀为组织记录。

## 情境

周会是量潮的内部管理机制：CEO办公室、COO办公室、CTO办公室三个部门汇报本周简报，上会提案逐个讨论并当场投票，结论写入纪要文档，会后向「量潮科技大群」播报结果。

角色分工：

- 主持人：推进议程，引导提案人讲清背景，开放讨论并控制节奏；
- 书记员：维护纪要文档，记下关键分歧、结论、投票结果与后续动作，散会前补完。

## 会前准备

1. 确认角色：本周谁是主持人、书记员；
2. 收集提案：会前催一遍提案人，收齐本周上会提案的 wiki 链接；
3. 收集简报：收齐三部门各自的本周简报文档链接；
4. 建纪要文档：从上周纪要「创建副本」，标题改为「2026年第X周-会议纪要-周会」，清空讨论与投票部分，保留骨架。

## 会中流程

1. 过一周简报：三部门按 CEO → COO → CTO 的固定顺序汇报；
2. 讨论提案：逐个提案过，主持人引导提案人讲背景、开放讨论；
3. 投票：每个提案讨论完当场投票，书记员同步记录。

## 纪要文档结构

纪要文档按固定区块组织：

| 区块 | 写什么 | 注意事项 |
|---|---|---|
| 元数据区 | 主持人、书记员 | 用飞书 @ 人，不手写名字 |
| 议程组1 | 固定议程（如宣读上周待办） | 没有就留空标题，保留区块 |
| 议程组2：部门简报 | 按部门列三行，每行 @ 部门参会人并贴本周简报文档链接 | 顺序固定为 CEO → COO → CTO |
| 研讨 | 自由研讨环节的要点 | 没有就留空 |
| 提案 | 本周上会提案的文档引用卡片，按讨论顺序排列 | 用飞书文档引用卡片；顺序=讨论顺序=播报顺序 |
| 讨论 | 每个提案的结论、投票结果与后续动作 | 核心留档区，散会前补完 |

## 会后播报

散会后由书记员在「量潮科技大群」发一条编号播报，顺序与纪要「提案」区一致，格式为「提案——结果」，可附一句后续动作。示例已按案例库脱敏约定类型化：

> 1.某需求类提案——通过
> 2.某治理类提案——通过，后续按此分配到审批流程
> 3.某人事类提案——通过
> 4.某流程类提案——通过，确认相关工作统一按「计划 → 编写 → 评审 → 修改 → 定稿」工作流推进
