# 批量发送实训基地入群邀请

本案例记录招聘流程的第一条管道：HR 邮箱收到投递邮件后，系统自动回一封带群邀请链接的实训邀请邮件，候选人状态由「投递」进入「邀请已发」。全程无人参与。案例沉淀为六条意图规则、一份机器可读的迁移规格与一个通用执行器。

## 需求

### 情境

候选人把简历投到 `hr@quanttide.com`，公司通过飞书邮箱接收。系统要在收到投递后自动回一封「量潮实训基地」邀请邮件，正文含一条群邀请链接，让人点链接进群——入口是收件箱里的一封投递邮件，出口是状态「邀请已发」。约束有四：全程无人参与；正文话术取自业务手册，入口是群邀请链接而非二维码附件；发送失败不得推进状态；同一份流程 YAML，Python 实验室与 Rust 执行器要跑出一致输出。

### 难点

难点有四：

- 投递识别不唯一：HR 处理邮件时会把投递移进「沟通面试中」等文件夹，只扫收件箱会漏；有效投递还可能被 Spam 误判，且 Spam 里的附件下载受限；
- 发信有前置：正文模板要嵌群邀请链接，链接必须在发信前先取；而实训基地群是外部群，机器人身份取不到链接，真取要用 HR 用户身份；
- 失败语义：动作要先做、失败就整轮报错——状态一旦与事实分叉，后面每一格都跟着错；
- 入口有寿命：群邀请链接非永久（实测 `is_permanent: false`），过期后重发是常规动作；

## 意图

### 自然语言规则

1. 收到即回：迁移不写检查，候选人进入「投递」格即无条件推；
2. 先取后发：发信前先取群邀请链接，按 `as` 起名，正文模板用 `{{邀请链接}}` 引用；
3. 动作先做：推格前先执行动作，失败整轮报错、状态不挪；
4. 状态可重建：进人以收件箱为准，状态可从飞书侧原始数据重建；
5. 话术照手册：正文取自业务手册的「邀请进群」话术，入口由二维码改为群邀请链接，落款「量潮招聘」；
6. 对照为证：以与实验室逐行相同的输出为成功判据，不以「跑通」为判据。

### 形式化规则

```text
对象：候选人 c（收件箱投递），流程 F，执行器 R

前置条件
  delivered(c) ∈ 收件箱 ∧ email(c) 合法
  可取群邀请链接 ∧ 可用 HR 用户身份

操作
  recognize(F, c)   从收件箱认出投递，登记为待发邀请的候选人
  prepare(F, c)     取一条群邀请链接
  send(F, c)        把链接按手册话术写进正文发给候选人
  record(F, c)      把候选人记为「邀请已发」，记下送达时间

不变式（发邀请后必须全部成立）
  I1 出口：状态(c) = 邀请已发
  I2 送达：正文含群邀请链接
  I3 原子：任一步失败 ⇒ c 的状态与记录均不变
  I4 留痕：成功则记下送达时间
  I5 对照：输出与实验室参照逐行相同
```

## 规格

### 自然语言描述

管道分四步，每步以前一步的产出为输入，以可核对的结果收尾：

1. 认出投递：收件箱里的未读投递（未读即未处理），按发件人登记为待发邀请的候选人；结果＝同人重复投递只留一条，取最早日期，其余重复随此人一并归档。
2. 备邀请链接：为候选人取一条群邀请链接；结果＝拿到一条可点的链接。
3. 发邀请邮件：链接按手册话术写进正文发给候选人；结果＝邮件送达。
4. 记状态：候选人由「投递」变为「邀请已发」；做法＝投递邮件标记已读，移入 HR 邮箱文件夹「已发送实训邀请」（旧流程的「已邀请入群」）；结果＝状态更新、记下时间，收件箱不再留这封投递。

两条不论怎么实现都成立：任一步失败则本轮中止、候选人不前进；同一份流程定义，Python 与 Rust 两侧结果逐行相同。

批量分轮跑：每轮固定人数（10 人），跑完一轮再跑下一轮，直到未读清空；轮内候选人按投递日期从晚到早逐个走完四步，每封间隔 2-10 秒，每轮之间再停几秒，两层节流防并发写入冲突。群邀请链接每轮取一次、轮内复用，过期重取。循环只补三条规则——已发过邀请的跳过（归档文件夹查得到同人「量潮实训基地邀请」），姓名解析不出或缺邮箱的跳过进人工清单，单人任一步失败只记失败清单、状态不动、继续下一人，轮末按失败清单补跑。结束交一份报告：每人发送时间，附成功与失败清单。

### YAML 描述

机器可读的规格表示，与上面四步一一对应。

```yaml
收集:
  邮箱: hr@quanttide.com
  范围: [收件箱, 沟通面试中, Spam]     # 仅收件箱进人，其余是补拉留档范围

迁移:
  - 从: 投递
    到: 邀请已发
    触发: 收到投递，直接发实训邀请
    执行者: 系统
    动作:
      能力: send_mail
      先取:
        - 能力: chat_link
          as: 邀请链接
      参数:
        to: "{{候选人.邮箱}}"
        subject: 量潮实训基地邀请
        body: |-
          {{候选人.姓名}}你好，感谢你对量潮科技的关注与投递。经评估，诚邀你加入量潮实训基地。

          实训基地是量潮科技对外招聘考核的组成部分。你将在这里通过完成真实的工作任务接受考核，以实际产出代替答卷。

          请加入实训基地群，进群后修改昵称为「{{候选人.姓名}}-岗位意向」：{{邀请链接}}

          具体考核规则将在群内发布，请关注群公告和资料。

          期待在基地见到你。

          量潮招聘
    副作用: 标记已读，移入文件夹「已发送实训邀请」，记发送时间

批量:
  分轮: 每轮固定人数（10），多轮到未读清空；轮内逐人执行上面的迁移，投递日期从晚到早
  取链: 每轮取一次，轮内复用，过期重取
  跳过: 已发过（归档文件夹查到同人邀请）、姓名解析不出、缺邮箱
  失败: 记失败清单，状态不动，继续下一人，轮末补跑
  间隔: 每封 2-10 秒，每轮之间再停几秒
  报告: 每人发送时间，成功与失败清单
```

> 提示：范围里的「沟通面试中」「Spam」只用于补拉留档与人工核对，进人仍以收件箱为准。

## 实现

管道本体是四条 `lark-cli` 调用——读收件箱、取群邀请链接、发邀请邮件、记状态；另有两件一次性准备，做一次即可。

一次性准备：

```bash
MAILBOX=hr@quanttide.com

# 定位「量潮实训基地」群的 chat_id
CHAT_ID=$(lark-cli im +chat-search --query 实训基地 --as user --format json \
  | jq -r '.data.chats[] | select(.name=="量潮实训基地") | .chat_id')

# 文件夹 id：记状态移入「已发送实训邀请」要它，补拉留档与人工核对也用它；进人不依赖它
lark-cli mail user_mailbox.folders list --user-mailbox-id "$MAILBOX" --format json
```

管道本体（每个投递重复一遍；批量就是把下面四步套进循环）：

```bash
# 1 认出投递：列收件箱摘要，发件人即候选人邮箱；不带 filter 即默认收件箱，与规格「仅收件箱进人」对齐
lark-cli mail +triage --mailbox "$MAILBOX" --max 50 --format json

# 2 取群邀请链接（外部群机器人身份取不到，得用 HR 用户身份）；链接非永久，过期后重发是常规动作；批量时此步每轮一次、轮内复用
lark-cli im chats link --chat-id "$CHAT_ID" --as user --format json

# 3 发邀请邮件：手册「邀请进群」话术，正文填姓名与链接；姓名从投递主题解析，
#    主题格式为「岗位-姓名-学校-时长」，取第二段（如「产品运营-张三-某高校-6个月」→ 张三）
lark-cli mail +send --mailbox "$MAILBOX" --to "$候选人邮箱" \
  --subject '量潮实训基地邀请' \
  --body "$候选人姓名你好，感谢你对量潮科技的关注与投递。经评估，诚邀你加入量潮实训基地。

实训基地是量潮科技对外招聘考核的组成部分。你将在这里通过完成真实的工作任务接受考核，以实际产出代替答卷。

请加入实训基地群，进群后修改昵称为「$候选人姓名-岗位意向」：$邀请链接

具体考核规则将在群内发布，请关注群公告和资料。

期待在基地见到你。

量潮招聘" \
  --confirm-send --as user

# 4 记状态：投递邮件标记已读并移入「已发送实训邀请」文件夹（旧流程叫「已邀请入群」），
#    一条 modify 同时做两件事：remove_label_ids 摘掉 UNREAD 即已读，add_folder 即移入
lark-cli mail user_mailbox.messages modify \
  --message-id "$投递message_id" --user-mailbox-id "$MAILBOX" \
  --data '{"add_folder": "<已发送实训邀请 folder_id>", "remove_label_ids": ["UNREAD"]}' \
  --as user --format json
```

```bash
# 批量：分轮跑，每轮固定人数（10），多轮到未读清空；取链每轮一次
每轮人数=10
split -l "$每轮人数" /tmp/待发邀请清单 /tmp/轮次.   # 待发邀请清单按投递日期从晚到早排序，每轮一个清单文件

for 清单 in 轮次.*; do
  邀请链接=$(lark-cli im chats link --chat-id "$CHAT_ID" --as user --format json | jq -r '.data.share_link')
  while read -r 候选人邮箱 候选人姓名 投递message_id; do
    # 跳过：已发过（按收件人+主题在「已发送实训邀请」查得到）、姓名解析不出、缺邮箱
    # 1、3、4 同上（第 2 步用本轮链接）；任一步失败记入失败清单、continue，状态不动
    sleep 6 # 每封 2-10 秒；撞 Concurrent write conflict 记失败清单、轮末补跑
  done < "$清单"
  sleep 5 # 轮与轮之间再停一下，进一步降写入频率
done
# 全部轮次结束交报告：每人发送时间 + 成功/失败清单
```

批量执行的临时脚本与中间清单写在系统 `/tmp` 目录，跑完即删，不进仓库。

发后核对，回读发件箱按主题匹配；不属于管道四步，不作推进条件：

```bash
# 回读发件箱
lark-cli mail +triage --mailbox "$MAILBOX" --filter '{"folder":"SENT"}' --max 10 --format json

# 也可按归档文件夹核对：先列文件夹拿 id，再按 id 读（记状态即归入「已发送实训邀请」）
lark-cli mail user_mailbox.folders list --user-mailbox-id "$MAILBOX" --format json
lark-cli mail +triage --mailbox "$MAILBOX" --filter '{"folder":"<folder_id>"}' --max 100 --format json
```

批量发送时 `lark-cli` 有并发写入限制，每封之间间隔 2-10 秒；实测 2 秒仍会撞 Concurrent write conflict（首轮 10 封撞 2 封），撞上就记失败清单、轮末补跑。

投递缺邮箱的候选人（如通过飞书访客账号投递、未留邮箱）不满足前置条件 `email(c) 合法`，不进「待发邀请」；由人补邮箱后下一轮再发，或跳过单独处理。

执行器把四条管道调用按流程串起来、管状态。案例执行结果：收件箱里的投递各收到一封带群邀请链接的邀请邮件，候选人由「投递」记为「邀请已发」。
