# 提取代金券发放记录

本案例记录教学实训群的一条数据管道：群里的消息流向一份可对账的代金券发放记录。入口是群聊原文，出口是带编号、合计与缺口说明的发放记录，出群前过一道脱敏。管道本体机器跑，脱敏复核与口径裁定留给人。

## 需求

### 情境

组织以代金券给成员的行为与成果定价，发放动作本身只留一条群消息。发放有两种走法：按既定制度由公司方直接发，或按管理者的政策需求在群内公开发。两种走法都没有统一编号，也没有逐笔的账本回执，于是三件事无从核对——谁拿过、同一个人拿过几次、账上是否都有。

管道要做的就是从群聊里把这些发放消息捞出来，收敛成一份记录：入口是群内全部消息，出口是一张发放记录表。约束有四：只能用群消息这一份数据源，不补录、不臆测金额；关键词检索与全量扫描两路必须收敛到同一批消息；金额以消息原文为准，组合表述按明细拆分；出群前人员与链接一律换成角色与位置描述。

### 难点

难点有四：

- 检索有缺口：同一件事在群里写作「代金券」、「优惠券」、「券」三种，只用「代金券」会漏，只用「券」会带进与代金券无关的票券讨论；
- 发放与讨论混在一起：制度定价、他人提请、政策公布、事后答疑都带金额与券字，但它们不是发放；
- 金额是组合表述：「主额 500 加追加 500 共 1000」、「追加 2 张 100」，按整句记会漏追加，按字面相加会把「共」重复计入；
- 出口要脱敏：记录出自内部群，人员姓名、群标识、消息链接、内部域名不能跟着出门。

## 意图

### 自然语言规则

1. 单源取数：只以该群的群消息为数据源，不跨群、不补录；
2. 并集检索：关键词至少覆盖「代金券」「券」「奖励」「发券」，取并集而非任一单查；
3. 双路收敛：再拉全量消息逐条匹配「券」「奖励」「奖金」交叉验证，两路不一致以全量为准；
4. 三要素判发放：同一条消息内同时给出接收人、金额、事由才算发放，缺一不算；
5. 金额照原文：主额与追加分段拆分，合计以分段之和为准，不采信口头的「共多少」；
6. 缺口照实：无账本回执、预算未落地、口径未定等照录，不为凑整而删改；
7. 出群脱敏：人员换角色、机构换类型名、链接与标识清零、原话改叙述，业务数据保留。

### 形式化规则

```text
对象：群聊 G，消息集合 M，发放消息集合 P，记录集合 R

前置条件
  G 为成员实际参与的教学实训群
  M = 群内全部消息（含取数截止时间）
  P ⊆ M

操作
  collect(G)    拉取 G 的全量消息，登记取数截止时间
  filter(M)     关键词并集检索 + 全量逐条匹配，两路交叉
  locate(M)     在候选集中按三要素判定发放消息，得到 P
  record(P)     一条发放消息落一条记录，编号为日期加序号
  mask(R)       人员、机构、链接换角色与位置描述
  verify(R)     合计与按接收人汇总互校，缺口条目核对

不变式（记录交付时必须全部成立）
  I1 单源：R 的每一条都能回溯到 M 中的一条消息位置
  I2 收敛：关键词并集结果 = 全量匹配结果，否则以全量为准并记录缺口
  I3 互斥：讨论、提请、政策、答疑四类不进入 P
  I4 对账：合计 = 按接收人汇总之和
  I5 缺口：无法对账的条目照实保留，不出门时一并保留
  I6 脱敏：R 中无人员姓名、无群标识与消息链接、无内部域名
```

## 规格

### 自然语言描述

管道分五步，每步以前一步的产出为输入，以可核对的结果收尾：

1. 定群：按群名搜索拿到群标识，全流程只用这一个群；结果＝一个群标识与取数截止时间。
2. 筛相关消息：关键词检索取并集，再全量拉取逐条匹配做交叉；结果＝一份候选消息清单，两路条数一致或差异可解释。
3. 定位发放消息：按接收人、金额、事由三要素逐条判定，讨论、提请、政策、答疑四类剔除；金额组合表述拆成主额与追加；结果＝发放消息清单与逐条金额明细。
4. 落记录：一条发放消息一条记录，编号按日期加序号，文末给合计与按接收人汇总，两者互校；结果＝内部版记录，可直接与账本对账。
5. 脱敏出群：按出群规则逐项替换人员、机构、链接，原话改叙述，业务数据与缺口保留；结果＝可公开的记录，事实与内部版一致，人员不可见。

人工接手点有两处：第 3 步的三要素判定不由脚本硬判，脚本只收到候选清单，逐条由人过；第 5 步出群前由人复核金额拆分、缺口保留与角色关系，签字后才入库。

### YAML 描述

机器可读的规格表示，与上面五步一一对应。

```yaml
收集:
  群: 教学实训群（群名检索定位，全流程唯一数据源）
  截止: 取数时点，写入记录

迁移:
  - 从: 群消息
    到: 候选消息清单
    触发: 全量拉取完成
    执行者: 系统
    动作:
      检索: ["代金券", "券", "奖励", "发券"]
      全量匹配: ["券", "奖励", "奖金"]
      合并: 取并集，两路比对
    副作用: 记录两路条数与差异原因

  - 从: 候选消息清单
    到: 发放消息清单
    触发: 三要素齐备
    执行者: 系统给候选，人逐条判
    动作:
      保留: 同一条消息内同时给出接收人、金额、事由
      剔除: [制度与定价说明, 他人提请, 政策公布, 发放后答疑]
      拆分: 主额与追加分段，合计取分段之和
    副作用: 无对账凭据的条目打缺口标记

  - 从: 发放消息清单
    到: 内部版记录
    触发: 逐条落表
    执行者: 系统
    动作:
      字段: [编号, 时间, 接收人, 金额, 事由, 发放人, 消息位置]
      编号: 日期加序号
      互校: 合计 = 按接收人汇总
    副作用: 缺口说明随表输出

  - 从: 内部版记录
    到: 可公开记录
    触发: 出群
    执行者: 系统执行，人复核
    动作:
      换: 人名→职务与身份加序号，机构名→类型名
      删: 群标识、消息链接、内部域名
      改: 原话改事实叙述
      留: 金额、日期、事由、角色关系、缺口条目
    副作用: 人工复核签字后入库，不签字不放行

校验:
  单源: 每条记录可回溯到具体消息位置
  收敛: 关键词并集与全量匹配条数一致
  对账: 合计等于按接收人汇总之和
  脱敏: 全文无姓名、无群标识与链接、无域名
```

> 提示：口径判不准时机器不猜——提请、政策、答疑三类若同时出现金额，按「无明确接收人」处理，进候选清单但不进发放清单，等人裁定。

## 实现

管道本体是三次 `lark-cli` 调用加两段本地处理。

```bash
# 1 定群：拿 chat_id，后续全部只认这一个群
CHAT_ID=$(lark-cli im +chat-search --query 实训基地 --as user --format json \
  | jq -r '.data.chats[] | select(.name=="量潮实训基地") | .chat_id')

# 2 关键词并集检索：逐个关键词查，落成文件，本地取并集
for 关键词 in 代金券 券 奖励 发券; do
  lark-cli im +messages-search --query "$关键词" --chat-id "$CHAT_ID" \
    --page-all --format json --as user > "/tmp/$关键词.json"
done

# 3 全量拉取交叉验证：page-all 一次到底，--no-reactions 省掉表情回查
lark-cli im +chat-messages-list --chat-id "$CHAT_ID" \
  --order asc --page-all --page-limit 100 --no-reactions \
  --format json --as user > /tmp/全量消息.json
```

两段本地处理：匹配与分类用一次脚本，落表与脱敏用一次脚本。

```python
# 4 收敛与分类：全量匹配与关键词并集比对，输出候选清单供逐条判定
import json, re, html

全量 = json.load(open("/tmp/全量消息.json"))["data"]["messages"]

def 正文(m):
    c = m.get("content") or ""
    if isinstance(c, dict):
        c = json.dumps(c, ensure_ascii=False)
    return re.sub(r"\s+", " ", html.unescape(re.sub(r"<[^>]+>", " ", c))).strip()

候选 = [m for m in 全量 if re.search(r"券|奖励|奖金", 正文(m))]

print(len(全量), len(候选))   # 实测 2915 / 52，关键词并集 53 条，差的一条是合并转发，正文不可解析
```

脚本只负责把候选收到 52 条，不再往下猜。三要素齐备与否逐条人工判：同一条消息里同时出现接收人、金额与事由才进发放清单，讨论、提请、政策、答疑四类剔除。本案例 52 条中判出 10 条发放，其余 42 条归入四类。

```python
# 5 落表与脱敏：编号按日期加序号，合计与按接收人汇总互校，出群前全员换角色
#    内部版与公开版同源生成，脱敏只是字段映射，不动金额与事由
映射 = {"张三": "CEO", "李四": "基地秘书长", "王五": "候选人甲"}   # 人复核后填写，不入仓库
def 脱敏(记录行):
    return {**记录行,
            "接收人": 映射.get(记录行["接收人"], "候选人"),
            "发放人": 映射.get(记录行["发放人"], "公司方"),
            "消息位置": "群内消息"}
```

机器跑完输出两份表：内部版带接收人姓名与消息位置，可与账本逐条对账；公开版只留角色，用于出群。

人工接手点两处，分别在第 3 步与第 5 步。第 3 步人过分类：逐条看是否同时给出接收人、金额、事由。第 5 步人过出口：复核三件事，金额拆分是否与消息原文一致，缺口条目是否照实保留，脱敏后的角色关系是否仍能还原事由。签字前不入库。
